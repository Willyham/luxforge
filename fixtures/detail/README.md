# Detail fixtures

`cases.json` contains deterministic image specifications, all eight field values, per-axis sampling scales, mask coverage and complete independent f64 linear-sRGB outputs. Inputs are generated from specifications rather than stored photographs. Coverage includes identity, constants, impulses, grey/saturated ramps, signed/HDR values, gratings, colour boundaries, 8×8 JPEG blocks, slanted edges, noise, 1×1/2×3/17×5 inputs, a 512-pixel tile cut, masks 0/0.5/1 and sampled reductions 2/3/4/6/8 with unequal axes.

`measurements.json` holds every per-configuration synthetic metric and its proposed minimum or maximum. Failing rows are preserved. Numerical dispositions and frozen equations live in `docs/design/detail-study.md`; these fixtures do not establish photographic quality or native performance.

Generate with `cargo test -p luxforge-reference --test studies -- --ignored generate_detail_fixtures`. `detail_fixtures_match_reference` and `detail_measurements_match_reference` reload and recompute independently. The generator writes only the cases and measurements; it preserves the photographic corpus manifest.

`production-measurements.json` records the same synthetic probe constructors/metrics through the actual byte/linear render and preview queue, including all failed rows. `production_probes.rs` first verifies that extracting callback evaluators has left the independent measurement fixture unchanged. It then measures denoise alone and the combined moderate Detail settings, terminal chroma, the moving proxy versus the actual settled reduction, and the complete Detail → Basic dark ramp. Terminal Original-relative chroma figures are supplementary diagnostics; they do not replace the prescribed gate.

The standalone evidence utilities link to already-built debug crates, avoiding another concurrent Cargo build: run `python3 fixtures/detail/build_utilities.py` from the repository. With a current core/reference build it writes the executables `detail-render-corpus` and `detail-production-probes` to the system temporary directory. Run the first with a private RAW manifest, an authentic JPEG path and a **fresh** evidence directory (an optional fourth argument selects one manifest key). Run the second with `fixtures/detail/production-measurements.json` to regenerate the full-pipeline synthetic report. Neither launches the GUI or performs a timing run.

`render_corpus.rs` verifies each original SHA256 before and after processing. It uses `EditorService::render_current` for baseline, moderate, noise-stress and sharpen-stress full frames, saves each listed 100% crop as PNG, and saves final-size views from the exact raster via the shared `PreviewIntent::Reduce` path at 1024×1024 bounds. Images and correlated render manifests stay under ignored `artifacts/`; the study records their current dispositions. The corpus includes a fourth Nikon face/hair crop because its first three crops are defocused and cannot establish skin preservation.
