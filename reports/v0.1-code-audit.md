## Follow-up findings and decisions

### O01 — P1: permanent deletion and no-op navigation were unsafe to retry after cache loss

The public API reproduction showed a no-op Undo consuming a newer pick after restart and a
retried Empty Removed deleting a photograph removed after the first request. Originals remained
unchanged, but catalog history was lost. The 256-answer / 8 MiB owner cache could not provide
restart or eviction safety, and asset-scoped request rows could not survive permanent deletion.

**Implemented; worth the schema change before release.** A dedicated immutable catalog request
table records canonical input identity and complete synchronous results in the mutation transaction,
including no-ops. Async admissions freeze resolved inputs before work; live retries join the same
job, completed retries reconstruct its terminal answer, and interrupted work requires a new request
ID. Deletion cannot remove these records. Results/admissions have an explicit 256 MiB limit. The
request scope now covers library navigation, organization, versions, presets, batches, Locate,
merge mutations and artifact collection. External settings and session-only operations retain their
separate bounded owner cache; no blanket restart guarantee is claimed for them.
Durable answers bypass that cache entirely, avoiding duplicate serialization and storage and
preventing them from evicting useful session replies. Both synchronous and deferred paths are covered.

Catalog format is **2**. Older pre-release catalogs are explicitly refused, preserved byte for
byte, and never migrated or silently replaced. This follows the existing current-shape-only policy.
Regression coverage includes restart, eviction, input conflicts before dynamic target resolution,
no-ops, rollback, later deletion, frozen selection, interrupted work and worker-start failure.
[Request storage](../crates/luxforge-core/src/editor/catalog_requests.rs),
[owner regressions](../crates/luxforge-core/src/api/owner/library/durable_requests_tests.rs).

The original pre-fix reproduction is retained under
[retry-reproduction](../artifacts/v01-audit/retry-reproduction/requests-and-answers.jsonl).
The follow-up uses the same public `luxforge-json` request sequence with reversed assertions;
its actual result is recorded with the validation below.

### O02 — P2: source.check could clear a known byte mismatch using metadata alone

An in-place change can preserve identity and length. Preparation/export still refused the wrong
bytes, but a presence check could misleadingly clear the known Changed state.

**Implemented; worth fixing without archive-wide hashing.** A persistent mismatch flag survives
Missing/Offline observations. Only known-changed originals gain streamed, cancellable fingerprint
verification on the library worker; healthy presence checks remain metadata-only. Commit validates
the locator, verified signature and integrity generation, so a newer refusal invalidates older
proof even when the file signature is unchanged. Restored original bytes can recover.
[Implementation and tests](../crates/luxforge-core/src/library/availability.rs).

### O03 — P2: shared resource storage had only per-owner transfer exclusivity

Two catalogs could race deterministic staging, final publication and quota admission. Pinned hashes
prevented admission of corrupt data but did not prevent lost installs or excess quota.

**Implemented; worth global serialization at this shared boundary.** An OS advisory resource-root
lock runs on the worker, waits cancellably, rereads installed state/quota after acquisition and
covers publication, removal and cleanup. Tests cover same-resource reuse, quota, install versus
remove, process locking and cancelled waiters. Unique staging alone would not repair quota races.
[Resource coordination](../crates/luxforge-core/src/capabilities/resources.rs).

### O04 — P2: errors after publication were reported like unpublished writes

A directory-sync failure can follow a visible rename. Treating it as an ordinary failed write
could leave grants/settings and their side effects inconsistent, or discard referenced artifacts.

**Implemented across publication callers; worth the coordinated change.** Published failures retain
an explicit error with `published: true`, `durable: false` and the path. Owners reconcile visible
state, cancellation and events; the initiating UI rereads affected preferences, settings, resources,
themes and export presets while retaining the error. Artifacts retain referenced bytes. Export
retains its visible file; batch errors include the partial report, survive late cancellation and
are durable across retries. Resource removal separately reports a visible uninstall if cleanup
fails after deleting its marker. No blind rollback or successful-durability claim is substituted.
[Publication outcome](../crates/luxforge-core/src/atomic_file.rs),
[shared-state regressions](../crates/luxforge-core/src/capabilities/shared_state_tests.rs).

### O05 — P2: global permission revocation cancelled only the current owner's jobs

Captured permission allowed already-admitted work in another catalog owner to send after revocation.

**Implemented; worth preserving consent across owners.** Every send/download rechecks the grant
identity and full captured endpoint. A lazy native watcher exists while relevant work is active;
revocation/profile changes cancel queued work, controls and sockets and wake the owner. Missing,
unreadable or unwatched permission state fails closed. Same-origin endpoint changes also invalidate
captured work, even if a subsequent grant-file write fails. Deterministic tests cover policy;
a separate-process native test covers real Linux watcher delivery. macOS/Windows delivery remains
a native qualification gate. There is no always-on idle poll.
[Permission observation](../crates/luxforge-core/src/capabilities/permission_watch.rs).

### O06 — P2: hard vignette precision boundary confirmed; reference fallback selected

For a white 20 × 20 stage with amount -100, midpoint 65, roundness 0, feather 0, the f64 reference
radius at (6,1) is just below 0.65 while a stepwise f32 evaluation of the shader is just above its
narrowed threshold. Eight symmetric pixels are predicted to switch white to black. That would
violate aggregate pointwise tolerance on this legal small stage. The same coordinates occur in
a 6020 × 6020 photograph; no whole-photo aggregate failure is inferred from eight pixels.

**Worth a narrow fallback for pre-release correctness.** The committed
[vignette device test](../crates/luxforge-app/src/app/gpu_colour_tests.rs) subsequently confirmed
failures at Feather 0 and 0.0001 on hosted Metal. A non-neutral computed normalized span below
0.001 now declares `no-program` and uses the existing whole-frame reference. This is a conservative
admission boundary, ten times the first passing sampled span and a thousand times the failing
positive span, not a theorem about every GPU's arithmetic. Default Feather 50 remains on the GPU.
The frozen oracle and tolerance do not change. Adapter-free tests check the named fallback for
ordinary and qualification requests and every output pixel against the independent oracle;
supported spans keep actual shader/readback tests. A neutral GPU-shaped draft returns its input
unchanged. Extreme settings can render more slowly; native cost and wider corpus qualification
remain open. The original no-adapter skip below describes the earlier local run, not the later CI
evidence that confirmed the defect.

## Architecture, duplication and dead-code decisions

- Keep the UI-independent command service, immutable recipe snapshots, transactional history and
  source verification. The reviewed export publication paths refuse replacement of originals;
  no original-modification defect was established. Avoid replacing working ownership boundaries
  with a generalized graph or a new async framework for v0.1.
- Put invariants at every durable writer, not only forward planners. F01/F02 demonstrate the
  practical value: shared validation covers ordinary commands and undo/redo. Audit future
  journal item types against their inverse writes.
- Carry immutable identity across asynchronous work, including errors. F03/F05 were missing
  identity, not a need for additional polling or reloading all document state.
- Global files require global lifecycle coordination. O03/O05 show the limit of per-owner lanes;
  O01/O04 show why mutation outcome and publication point must be explicit. The follow-up addresses these
  ownership boundaries; cosmetic splitting of large files would not repair them.
- Keep GPU/reference implementations and independent oracle fixtures distinct. Similarity there
  provides verification value. Select/loupe caches and evidence journeys also have different
  ownership and acceptance contracts; no safe, high-value consolidation was established.
- Remove only the obsolete journal-response reconstruction helpers superseded by durable results.
  No speculative dead-code sweep. Reviewed `allow(dead_code)` examples hold native callback
  lifetimes, GPU retirement state, macro-generated identifier helpers or test/qualification
  seams. `MenuTarget` is used and the preview `never()` panic is a test sentinel. Removal would
  add risk without demonstrated benefit.
- Correct the architecture's stale unsafe-boundary inventory and Tokio description to match
  manifests. Preserve leaf-crate FFI boundaries; this review does not qualify every native
  callback or vendor implementation.
- Dependency pins and automated advisory/license policy passed with the repository's existing
  scoped exceptions. This does not complete the explicitly deferred manual licence/native/asset
  review or waive exception expiries.

1. No new original reads, hashes or decodes in editor interactions. Merge retry tests explicitly
   check no new input reads. Signing hashes package files on the release tool's path.
2. No new full-frame allocation. UI changes add identity/one-generation state; server shutdown
   retains at most the existing connection cap. Production prompt capture is removed. Native
   conditioning validates sizes before allocation (at most two fields, 2^28 f32 values per field);
   admission preflights headers/length without allocating payloads. Index collection charges its
   existing file/folder limits before growing its queues.
3. No point query, validation or no-op check renders a frame.
4. The owner gains bounded tree ancestry/sibling validation, not pixel work. Watch rebuilds run
   on the watcher worker. Large directory-tree recovery remains a platform cost to qualify.
5. Existing recipe tasks now carry their entry. Stale results are discarded without an extra
   asset/history/preview/upload request. Preference failure recovery uses its existing reread.
6. No new periodic timer, polling subscription or idle wake loop. Watch root addition explicitly
   wakes pending delivery; shutdown explicitly wakes retained sockets.
7. No new image cache. Signing adds bounded extraction/tree hashing; it is deliberately extra
   release admission work. No hit-rate, latency or memory improvement is claimed without data.
8. Native 24 MP before/after editor-performance was not run on this headless host. UI timing,
   watcher recovery at scale and native inference cost remain unqualified.
9. The Contrast equation is preserved but its numerically unstable small-slope evaluation is
   replaced on CPU/GPU and the f64 oracle. Independent high-precision equation fixtures and the
   pre-fix failing regression qualify CPU semantics without widening tolerance; native GPU
   readback and full corpus acceptance remain required. Other fixes use focused state/API/codec/
   native-parser tests, and rendered UI acceptance remains outstanding.
