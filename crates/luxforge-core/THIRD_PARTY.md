# Bundled JPEG codec native source

JPEG import decodes and JPEG export encodes with libjpeg-turbo as bundled and built by the `mozjpeg-sys` crate, through the `mozjpeg` crate's safe API and one type of `mozjpeg-sys`'s bindings, in one adapter module (`crates/luxforge-core/src/jpeg.rs`). The C source comes from the pinned crate in the Cargo registry and is compiled at build time with the `cc` crate and the platform's C compiler and linked statically. Nothing is downloaded at run time, no system libjpeg is loaded, and no CMake or NASM is used.

This software is based in part on the work of the Independent JPEG Group.

Export uses libjpeg's fastest profile (plain libjpeg-turbo behaviour: baseline, standard Huffman tables, no trellis quantization or progressive scans). libjpeg's errors unwind into Rust and are caught around every call; the decoder's own error manager also stops at libjpeg's first warning, so corrupt or truncated data is an error rather than grey fill. Decoded pixels do not depend on SIMD: libjpeg-turbo's test suite expects the same output from its integer IDCTs, upsampling and colour conversion with and without its SIMD extensions (only the floating-point DCT, which Luxforge does not use, varies), and the adapter's tests pin decoded digests so a platform that differed would fail. The crate's own `write_icc_profile` numbers ICC chunks from 0, which the ICC specification does not allow, so Luxforge writes its one ICC chunk with `write_marker` instead; its `icc_io` reader is not built, so the adapter reassembles a profile's chunks itself. Manual license and native review remains deferred; this file records provenance, not a completed audit.
