# Bundled diffusion native source

This crate builds stable-diffusion.cpp and its ggml from the source files in `vendor/` at compile time, with the `cc` crate only: no CMake, Python, network access or second build system. It is the editor's generative runtime (`docs/design/ai-editing.md`): the desktop and `luxforge-json` link it on macOS and Linux and hand it to the host through `HostConfig::inference`; the object removal probe (`probes/object-removal`) builds the same sources through its `diffusion` crate, which includes this crate's `native/build.rs` and `src/native.rs`. The vendored trees are pristine subsets of the upstream trees. `build.rs` stages one patched file, `src/pipeline/diffusion_engine.cpp`, into Cargo's `OUT_DIR` by exact-anchor replacement (each anchor must match exactly once, so an upstream change fails the build) and compiles that copy in place of the vendored one.

## Build

`build.rs` compiles six groups of objects with `-O3`, no debug information and `NDEBUG`, as C11 or C++17: ggml's C sources, ggml's C++ sources (with the Metal backend's C++ on macOS), the Metal backend's Objective-C (without ARC, as upstream builds it), the embedded Metal kernels, the third-party C, and stable-diffusion.cpp (upstream's source glob, less the patched engine and `src/tokenizers/vocab/vocab.cpp`, plus the staged engine and `native/vocab.cpp` and `native/shim.cpp`), and archives them all as one static library, `luxforge_sdcpp`, because GNU ld resolves one archive's members against each other whatever their order but not an archive against one linked before it, and these parts call each other in both directions. ggml-cpu's architecture kernels are `arch/arm/` on aarch64 and `arch/x86/` on x86_64, the only targets it builds. On Apple silicon it targets `-mcpu=apple-m1`, the M-series baseline, so the library runs on every M-series Mac rather than only the one that built it. Defines: `GGML_MAX_NAME=160`, `GGML_SCHED_MAX_COPIES=4`, `GGML_USE_CPU`, `_XOPEN_SOURCE=600`, on Linux `_GNU_SOURCE`, and on macOS `GGML_USE_METAL`, `GGML_METAL_EMBED_LIBRARY`, `_DARWIN_C_SOURCE`, `GGML_USE_ACCELERATE`, `ACCELERATE_NEW_LAPACK` and `ACCELERATE_LAPACK_ILP64`. It links Foundation, Metal, MetalKit, Accelerate and `libc++` on macOS and `libstdc++` on Linux. `ggml-version.h` is generated from the pinned version and commit; Oniguruma's CMake-generated `config.h` is replaced by the hand-written [`native/oniguruma-config.h`](native/oniguruma-config.h) for LP64 targets.

Upstream's `GGML_METAL_EMBED_LIBRARY` CMake step concatenates the Metal kernel sources into one string and assembles it into the binary. `build.rs` does the same per kernel: it inlines each kernel's `#include`d headers, writes the text to `OUT_DIR` and assembles a `.s` file whose `.incbin` holds it. The Metal framework compiles the kernels at first use and caches the result per user (16.4 s the first time on the M4 Pro, 15 ms afterwards). A host can warm that cache ahead of a generation: preparing an installed model initialises and releases one Metal device (`lf_sd_warm`). Linux builds compile the CPU backend alone, offered as `diffusion-cpu`; they are compile-checked, not qualified. Windows builds compile no native code: the crate offers no backend there, and a generative model is not offered.

## Local change

[`native/vocab.cpp`](native/vocab.cpp) replaces upstream's `vocab.cpp`, which compiles the 139 MB of generated tables into the library. A text encoder is given its tokenizer as a file (a Hugging Face `tokenizer.json`); without one, a context opened with a text encoder fails explicitly. A context opened without a text encoder still constructs its conditioner and a tokenizer it never uses, so for that context the tables are a one-merge stub.

The staged `diffusion_engine.cpp` changes three places, declared in [`native/luxforge_condition_hook.h`](native/luxforge_condition_hook.h) and defined in [`native/shim.cpp`](native/shim.cpp):

- it includes the hook header;
- `StableDiffusionGGML::get_learned_condition` first asks the shim for a supplied conditioning for the prompt and returns it without running the text encoder; otherwise it runs the encoder as upstream does and reports the result to the shim, which keeps it so it can be saved. A context opened without a text encoder refuses any prompt that has no supplied conditioning;
- for a context opened without a text encoder, the encoder's weights (`text_encoders.`) are added to the tensors the model metadata check ignores, so the absent file is not required. They are never loaded.

The shim's C ABI is private to this crate: it opens and closes a context, each holding its own supplied conditionings and whether it has a text encoder (the hooks find the context generating on the calling thread), reports the context's default sampler and scheduler, generates one image from borrowed RGB and mask buffers with an optional LoRA and reference image, cancels between steps, and saves or supplies a conditioning as a file (`LFSDCOND`, version 1: the `c_crossattn` and `c_vector` tensors with their shapes; any other field is refused). It catches C++ exceptions and returns the last error message.
