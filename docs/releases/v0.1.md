# Luxforge v0.1.0 — release notes draft

**Preparation draft. No v0.1 release or downloadable candidate exists yet.** The initial downloads target macOS and Linux together. Before publication, replace the release fields with verified facts and complete the practical preview checks in the [readiness assessment](../../reports/v0.1-code-audit.md#pre-release-readiness-re-audit). Luxforge is a free, open-source, non-destructive photo editor. This first preview brings browsing, photo selection and editing into a small desktop workspace, with the same operations available to scripts through a discoverable JSON command service.

## Included in the candidate scope

- Browse folders, pick photographs, develop selections into the catalog, organize them and locate missing originals.
- Edit with persistent history, undo/redo and named versions while the original files remain untouched.
- Adjust white balance, exposure and tone, the tone curve, sharpening and noise reduction, Texture/Clarity/Dehaze, the colour mixer and vignette.
- Crop, straighten, rotate and reflect; apply supported lens distortion and perspective corrections.
- Make local adjustments with linear/radial gradients, brushes, luminance and colour ranges.
- Clone or heal areas with the Corrections tools, retaining their operations in edit history.
- Develop supported RAW recording modes from sensor data, with continuous white-balance editing and the Standard look.
- Save presets, import supported Lightroom presets, copy/paste chosen settings and apply Auto tone per photograph.
- Export JPEG, WebP or 8/16-bit TIFF, with resizing, output sharpening, metadata choices and reusable presets; export selections in batches. Existing destinations and originals are never overwritten. JPEG quality 90 at full size remains the default.
- Choose a theme, inspect the histogram and clipping, compare the original and use live performance counters.
- Automate through `luxforge-json` and the running-session `luxforge-ctl` client. Tag builds package both alongside the editor.

This list is a candidate scope, not a claim of v0.1 qualification. Reconcile it with the frozen commit's [feature status](../features.md) before publication.

## Installation and updates to verify

For macOS: open the disk image (`.dmg`), drag **Luxforge** to the Applications folder beside it, eject the disk image and open Luxforge from Applications. A signed and notarized candidate should pass macOS's normal verification without disabling Gatekeeper or removing quarantine. Hosted signing is optional and must be enabled for that claim; no signed candidate or verified installation path exists yet. The macOS ZIP beside it holds the same app for updates. Final instructions must match the downloaded candidate's actual signing status.

The macOS CLI location is `Luxforge.app/Contents/Helpers/`; use the full executable path or add it to PATH yourself. No installer modifies your shell configuration.

For Linux: extract the tarball and launch `Luxforge/luxforge`. Both CLIs and runtime resources are beside it. Follow the packaged instructions for optional user-level desktop-entry/icon installation and removal. The candidate must be checked with a supported Vulkan driver, required shared libraries and a working XDG file-chooser portal on Wayland and X11. No root installer or automatic PATH change is planned. Linux installation is not yet verified.

The updater is implemented, but hosted update publication is not enabled and no public feed is qualified. Until a release provides a verified feed, updates are manual: quit the app and replace the application bundle or extracted Linux payload. The catalog, settings and logs live outside it. On macOS the current default is `~/Library/Application Support/Luxforge` for application data and `~/Library/Logs/Luxforge` for logs. Custom catalog locations stay where you chose them. Removing the app should leave that data and all originals in place; verify this on the candidate.

Keep backups of originals and catalogs. The catalog references originals; it is not a backup of the photographs. Catalog backups should use a closed app/owner and include the catalog's associated stored artifacts.

## Preview limits

This is pre-release software. The current catalog format is **2**. Only current catalog, recipe, API and module formats are supported; there are no migrations or compatibility guarantees between preview builds. Incompatible catalogs remain intact and require their matching older app or a fresh catalog for this preview. Retain data backups and the prior app when evaluating an update; returning to an older app does not ensure it can read newer data.

RAW admission is by the bundled camera and recording-mode catalog. A listed camera does not imply every compression/resolution mode works. Nikon High Efficiency NEF is refused; phone HEIC/Apple ProRAW remain unqualified. JPEG input supports the current sRGB/greyscale subset. Consult the [user guide](../user-guide.md#raw-development) for the supported scope.

The GPU renders the finished picture and exports within the declared tolerance against the CPU reference. Motion may use a reduced source and looks sharp again at rest. A machine whose GPU stage cannot run uses the reference renderer and reports that fallback. Cold shader compilation and heavy spatial stacks can delay work; total process/GPU memory and photographic Detail/RAW quality are not universally qualified. Do not describe provisional measurements as guaranteed performance or memory requirements.

Lightroom catalog import/alignment and MCP are outside this preview's implemented scope. Generative AI editing remains an experiment, off by default, with model distribution and further qualification open. Windows, Linux ARM64, Intel macOS and distributions outside the tested Linux baseline are outside the initial download matrix. Native Linux support remains unqualified; a tarball or hosted software-renderer result alone does not establish it. Optimised JPEG, file-size targeting and WebP can use substantial memory on large photographs; their export plans disclose that cost. Recheck these statements against the frozen candidate.

## Help and reports

Use the [user guide](../user-guide.md) for controls and scripting. Report problems through [GitHub issues](https://github.com/Willyham/luxforge/issues), with the app version, OS, chip/GPU, affected camera/recording mode and steps to reproduce. Include the visible error message or a small sanitized log excerpt. Check logs and screenshots for private photo paths or locations before sharing them; sample photographs and catalogs are optional and should only be shared with permission.

Luxforge is GPL-3.0-or-later. The release must include project and third-party notices, and matching source. The distribution-specific source/native/asset review is still open; this draft does not claim it is complete.
