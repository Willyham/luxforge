# Slider range and preset-readiness audit

Checked 2026-09-22 against the implemented Luxforge descriptors and the linked Adobe material. This is a comparison of **representable control values**, not a claim that equal values render the same pixels. Adobe Help describes most controls without publishing a complete current range table; entries marked *provisional* need a current Lightroom Classic UI or exported-preset check before an importer relies on them.

The sliders are generated from each module's parameter descriptors, which also define API validation. Display steps are 0.01 EV, 1 for most signed controls and tint, and 10 K for RAW temperature. These are UI hints: the API accepts in-range finite fractional values without rounding. Adobe's drag, keyboard and numeric-entry increments were not established by the sources above, so step equality is not claimed.

## Preset implication

The owner chose to retain Luxforge's validated RAW white-balance range and plan a conversion at preset-import time. The existing RAW model cannot safely accept the entire Adobe range: a sweep of the supported camera matrices found some 2,000 K / tint-above-100 combinations with an invalid whitepoint or sensor gains beyond Luxforge's finite limit. Extending descriptor bounds alone would create settings the renderer cannot process. The daylight-locus approximation also has no validated 50,000 K reference in the current numerical study.

A future importer must identify the source format and process version, distinguish RAW Kelvin/Tint from rendered-image relative white balance, convert only fields whose meaning has been calibrated, and report values it cannot represent. It must not clamp out-of-range values, silently omit an effect or treat identical slider labels as identical processing. Presets can contain profiles, curves, masks and other settings beyond the current Luxforge tool set; Adobe itself describes [partially compatible presets](https://helpx.adobe.com/lightroom-classic/desktop/kb/presets-faq.html). Matching numeric ranges is useful for representability, but it is not enough to reproduce the Lightroom rendition. The [preset importer](../../design/presets.md#import) follows these constraints: it transfers values only for the controls Luxforge has, refuses out-of-range values and RAW Kelvin and tint, and reports every other setting.
