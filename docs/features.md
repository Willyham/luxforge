| Draft conflicts with live agent commits | Implemented (M4) | Explicit Discard or Reapply; a stale draft keeps its composition and re-validates against the current stack |
| Resample stage boundary in the host pipeline | Implemented (M4) | Exact layers before and after compose as one raster pass each; at most two full frames exist at once, each within its JPEG 512 MiB or RAW planar 1.5 GiB frame limit |
| Number parameters and crop-frame canvas in descriptors | Implemented (M4) | `number` parameter kind and the `crop-frame` canvas interaction, generated into desktop controls and the JSON API alongside `point-pick` |
| Develop workspace shell | Implemented | Title bar, collapsible state and tools panels, canvas with the floating mode strip (pointer, canvas-takeover modes and view overlays), draft bar and notices, status bar; dark theme; verified on the M4 Mac by the `workspace` and `unavailable` smoke scenarios; [design](design/develop-workspace.md) |
| Widget library and layered desktop | Implemented | `lightwell-ui` (Iced only, no core dependency); `app/`, `state/` and `view/` layers with the boundary enforced by `cargo xtask check-repository`; [architecture](design/develop-workspace.md#architecture) |
| Generated control vocabulary | Implemented | Soft-range sliders, number fields, steppers, toggles, segmented/chip/menu choices, colour fields/pickers, multi-channel curves, groups, resets and styled actions with vector icons, and canvas pick buttons. Continuous gestures whose field is a whole request draft on the 16 ms tick and commit once; discrete controls commit once; no wheel editing. [UI components](design/ui-components.md) |

| Presence: texture, clarity, dehaze | Implemented | One `lightwell.presence` spatial-stage layer after the pointwise colour run, evaluated in 512 px tiles with the frozen halos on both the JPEG and RAW paths against the independent f64 [study](design/presence-study.md); `edit.set-presence` field patches, `edit.reset-presence`, the core draft lifecycle behind each slider; a point sample through the layer evaluates its tile, the declared exception to the point-query rule; measured cost and the missed slider target are in [performance](specs/performance.md) ([design](design/presence-mixer-vignette.md)) |
| Colour mixer: hue, saturation and luminance for eight ranges | Implemented | One `lightwell.mixer` colour-stage layer always evaluated after Basic, one Oklab unit against the independent f64 [study](design/mixer-study.md); `edit.set-mixer` field patches over twenty-four fields, `edit.reset-mixer`, gradient rails; verified on the M4 Mac by the `mixer` smoke scenario; per-colour view, targeted adjustment and B&W mix are not built |
| Vignette: amount, midpoint, roundness, feather | Implemented | One `lightwell.vignette` finish-stage layer after the geometry tail, so a crop update recentres it; one positional unit against the independent f64 [study](design/vignette-study.md); `edit.set-vignette` field patches with defaults for missing fields, `edit.reset-vignette`; verified on the M4 Mac by the `vignette` smoke scenario; one luminance-neutral style |
| Spatial processing primitive | Implemented | `Processing::Spatial` over declared units: a stage boundary evaluated in stage-aligned tiles with a summed halo bounded at 512 px, a separate 256 MiB spatial budget with batch-limited concurrency, cached global estimates, cancellation between batches, and one float output frame on the RAW path; [modules](design/modules-and-api.md), [architecture](design/architecture.md#rendering-and-limits) |
| Masks | In progress | Local adjustments as a host concept, authorized 2026-09-23 and phased in the [design](design/masking.md). **Implemented:** the recipe carries its masks and a layer an optional mask reference, in catalog format 5 and recipe format 2, with structural validation and retention of a component kind this build does not know; `render.transform` answers the geometry tail as one affine; the coverage mathematics is frozen by the [mask study](design/mask-study.md) against an independent `f64` reference, and the linear and radial gradients are transcribed from it bit-identically, each with a conservative support rectangle and a feature width; the `mask.*` host command family is declared with the same descriptor, control and generic-validation machinery a module action uses, drafted so one gesture is one entry, with labels that name the component and the mask and a destructive delete that names the layers it removed; a `maskable` effect flag — Basic, the colour mixer and Presence — puts one optional host-owned `mask` field on every action of such a module, with per-target `single_layer` and placement after the global layer in the mask list's order; **a masked colour layer and a masked spatial layer both change a picture**, blending the operation's output against its own input in linear light — inside the colour run before its single clamp, and at the tile write for a neighbourhood operation, leaving halos, tiling, the spatial budget and cancellation untouched — with the bounds rectangle skipping spans and copying tiles it cannot reach, on the byte and RAW linear paths, and a sample equal to the rendered byte; and the mask overlay is a bounded display-cell coverage grid the exact preview phase returns beside its frame, for a whole mask or one component, with its mode and tint as per-client view state that commits nothing. **Not built:** creating a radial through the commands (the command family declares its own geometry table, so the radial renders but cannot yet be made), brushes, non-AI range selections, the Mask panel and canvas, a mask target on a draft of a module action, and the proxy's supersample rule for features thinner than a proxy pixel. The path kind, the stroke list and the `brush-paint` capture are host primitives the Corrections brush geometry shares rather than duplicates |
