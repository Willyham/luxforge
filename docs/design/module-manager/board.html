Module manager · design board

Phase 1 turns built-in modules off and on and reorders the tools panel's sections and the mode strip's tools, as a person's preference outside every catalog. Phase 2 installs an external adjustment section from a package file the person chooses (a WASM sandbox with its CPU reference, plus a WGSL program the host validates), and in developer mode loads one from a folder. Install, uninstall and folder loads take effect on the next launch. There is no community index. Phase 2 boards have a dashed tag and are drawn only to show that phase 1 leaves room for them: nothing in them ships with phase 1.

Window boards are 1440 × 900 pt in Luxforge Dark. The Settings sheet keeps its delivered 720 × 480 pt size. The photograph is the owner's Sapa drone JPEG, as on the Develop boards. Values, counts and history are illustrative, and so is every external module named here (Split toning by h.okafor, Halation, Bloom): none of them exists. The design and its recorded defaults are in ../module-manager.md.

A Modules tab joins the Settings sheet after Appearance, with a four-square icon, listed in every build. One list, grouped by toolset (where a module's UI lives), each group in the person's order: Adjustments (tools panel sections), Corrections (band kinds), Tools (the mode strip) and Masking (New mask kinds), then Processing only. A row is a drag grip, the title, a one-line qualifier where it helps (Look: RAW photos only) and a switch, or a lock for a module that can't be turned off. An off row's title dims; it keeps its place, so turning it on again puts it back where it was. Selecting a row shows its detail: what it is, where it lives, where it renders in the fixed pipeline (with the stage underlined, and the sentence that the panel order doesn't move it), what happens to photos that use it, and its API. A change writes at once, like every other tab; preferences have no history entries, so the sheet offers a one-step Undo toast for the last change, plus Reset order per group and Reset all. The status bar behind says the same thing in words. The switch is module.enable / module.disable; a drag is one module.order.set.

Letters: the rule

Crop (R)
A tool's letter is its module's declaration. Moving a tool never changes it, and the tooltip keeps the delivered form, "Crop (R)". A tool that is off gives up its letter and its palette entry until it is enabled; nothing else takes the letter meanwhile.

When two modules claim one letter, the first claimant keeps it, built-ins first. A later one gets no letter rather than a substitute, and its tooltip and detail say whose the letter is. The palette still enters it. Phase 2's adjustment sections declare no canvas, so this is a rule for later kinds of module.

The ⋯ at the strip's end, after a rule, opens a menu upward listing every strip tool: a check to turn it on or off (one module.enable or module.disable), a lock for the host's Mask and for Crop, the letter, and Customize tools…, which opens Settings › Modules at Tools, where they are reordered (one module.order.set for the tools toolset). The same menu opens on a secondary click anywhere on the strip. Tools that are off stay listed here, unchecked, so they can always be found. In phase 1 the menu holds three tools and one switch, Corrections. The ⋯ is still worth its 26 pt because it is the only place on the canvas that says the strip is configurable. Reordering changes only where a tool sits, and Mask stays first.

Settings › Modules gains Install module… beside Reset all. It opens the system's file picker (not drawn) for a package file; the file name and extension here are illustrative. Luxforge reads the package's manifest (module.package.inspect {path}) and opens the one modal step, a review sheet. It names the module and version, says plainly that it comes from its author and that Luxforge hasn't reviewed it, and lists what it adds and where it renders. It shows the program it brings (a GPU program the host validates, or a CPU reference only) and the two capabilities a phase 2 module can never have, Network and Files, as quiet None rows. Then come the manifest's author, SPDX licence, source repository, version and interface, and the file. A manifest the host can't read, or one that declares anything but an adjustment section, refuses here with the reason and offers no Install. Install (module.install {path}) takes effect on the next launch; Escape cancels.

External modules sit in the Adjustments group beside the built-ins, ordered and switched the same way. A badge after the title says where the module came from: Community for one installed from a file, From folder (dashed) for one loaded from a folder in developer mode. A second badge at the row's end carries a state: Didn't load in the clipping red, quoting the loader's reason word for word from module.status, or Relaunch to apply in the accent. A module that fails to load keeps its place and its photos' edits. Load from folder… (module.folder.load {path}) appears only in developer mode. A folder module shows its path, picks up changes at the next launch (a reload is a relaunch) and is removed with module.folder.remove. There is no automatic update and no store of earlier versions: an update is a newer package file with the same id, chosen with Install module….

An update is a review sheet like Board E's, titled Replace … with …?. When the manifest says the new version can't read the formats existing edits use, the sheet says so in red and refuses unless confirmed: Replace anyway is red and not the default, and the photos keep their edits. When it can, the sheet reads like an install and its button is Replace. Uninstalling is the other confirmed step. Its dialog counts the photos in the open catalog that use the module and says what they lose, preview and export, not their data. Both take effect on the next launch. Afterwards the photo opens with the delivered Preview is stale notice naming the module, with Install module… beside it. Its band reads Not installed, and Export is refused with the reason in the status bar. History stays browsable and undo works, as for any unavailable effect.
