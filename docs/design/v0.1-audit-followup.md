# Release audit follow-up

Implementation authorized by the owner. This work closes the remaining advised code changes in
[the v0.1 audit](../../reports/v0.1-code-audit.md). Native qualification remains a separate final
gate; absence of hardware or private corpus inputs does not block independent fixes.

## Scope and settled choices

The implementation preserves originals, current command shapes where possible, the command
service boundary, existing numerical tolerances and bounded worker execution. Routine data
structures, test seams and file placement are delegated to implementers. No new dependency,
compatibility migration, generic coordination framework, timer on an idle owner, or public release
is required. The following describes the required behavior; implementation status lives in the
[task plan](../../tasks/project/v0-1-audit-followup.json).

### Durable catalog requests (O01)

Catalog mutations need durable identity, input matching and results independent of an asset's
lifetime. Use a dedicated catalog request table without an asset foreign key. Match the owner's
existing request namespace and hash the method and canonical input; retain no plaintext secrets.
Lookup precedes dynamic target resolution, with current authorization still enforced. Successful
no-ops are outcomes too. Record the result in the same transaction as the mutation, including
Empty Removed and navigation; the change journal remains change-only. A failed transaction
publishes neither its mutation nor its request result.

Batch and asynchronous library work must freeze resolved targets and settings before work can
commit. Exact live retries reuse the same admitted job; completed durable retries reconstruct a
finished answer. An admitted job interrupted by restart must not resolve a new selection or
silently rerun destructive work: it reports interruption and requires a fresh request ID. Changed
input for an existing identity is refused. Keep records required for retry safety when assets,
removed history or the bounded in-memory cache are deleted. Preserve bounded indexed lookups
and the existing limits on request/result and batch sizes.

The request table is part of the current catalog format; unsupported catalogs are rejected
explicitly before modification, under the pre-release policy, with no migration or silent
catalog replacement. Cover restart, cache eviction, changed inputs, no-op then
later mutation, deletion then later removal, batch target changes and interrupted admissions.

### Source availability (O02)

Keep ordinary availability checks metadata-first. They are presence checks, not an archive-wide
integrity scan. A previously fingerprint-confirmed Changed original can become Available only
after the worker streams and verifies its stored fingerprint, using the existing bounded buffer
and cancellation checkpoints. A mismatch stays Changed; restored original bytes can recover. A persistent integrity flag
retains known mismatches through temporary Missing or Offline observations; healthy archives
returning from an offline volume do not thereby acquire a full-content scan.
Owner commit must reject observations for a replaced locator and must not clear a newer Changed
observation using stale evidence. Each fresh Changed refusal advances a monotonic integrity generation; an observation from an older generation is discarded even if its file signature is unchanged. Recheck verified file signatures at publication.
No file hashing or decode is added to the owner or UI thread.

### Shared publication, resources and permissions (O03–O05)

Serialize resource installation, removal and cleanup across owners and processes with an OS
advisory lock at the shared resource root. Acquire it on the transfer worker, checking cancellation
while waiting; reread installed state and quota under the lock and hold it through publication and
cleanup. A cancelled waiter touches no staging or installed data.

Represent file publication separately from confirmed durability. Before rename an error leaves
the target unchanged; after rename a directory-sync error means the replacement is visible and
its durability is unconfirmed. Return an envelope/job error with `published: true`, `durable: false` and the affected path after
reconciliation, explicitly saying the replacement is visible but durability is unconfirmed. Do
not bury the failure in an ordinary success result. Reconcile visible settings,
events and permission cancellation, and never roll back by deleting referenced artifact objects.
Audit every atomic publication caller. Safe unreferenced data may remain for existing cleanup;
referenced data cannot be discarded to pretend a published write failed before publication.

Revalidate current grant and pinned profile origin before every send/download. Lazily observe
the shared permission/profile documents through the existing native watcher while relevant work
exists, cancel affected active controls (including sockets) and queued work across catalog owners,
and wake the owner through its existing messages. Missed-event recovery, deletion and unreadable
permission data fail closed for affected work. No permanent idle polling loop. Tests gate a send,
revoke from another owner and prove no later send; real-platform watcher qualification is separate
from deterministic policy tests.

### Appcast and usage ingress (O07–O10)

Appcast diagnostics retain original RSS item positions, including items discarded while parsing.
The ingestion global limiter uses rate accounting that preserves configured rates such as 3 and
600 per second instead of rounding their intervals down to milliseconds. Preserve burst capacity
and use fake clocks for the rate contract.

Cold feed reads are single-flight per target, so concurrent requests cannot each allocate another
maximum-sized feed. Keep hot responses shared and other targets independent. Preserve replacement
and bounds checks. Identifier expiry runs independently of statistics publication: entries expire
by the declared retention deadline even with long statistics/refill settings, and old entries are
expired before admission can refresh them. Use an expiry deadline/notification only while entries
exist, rather than an always-running empty-store timer.

### DNS cancellation (O11)

Keep the operating system resolver and address-class/rebinding checks, but isolate uninterruptible
lookups from request and owner lifetimes. Use a fixed, bounded process-level worker service with
bounded admission, deadline/cancellation-aware waiting and no thread per timeout. Literal IPs need
no worker. All returned addresses are still checked before connecting and a request resolves once.
Cancellation or deadline can return while the OS call remains blocked; abandoned lookups occupy
bounded capacity until the OS returns, and saturation refuses explicitly. Do not claim that the
OS call itself can be cancelled. Test a held resolver, cancelled waiter, expired request, queue
saturation and later recovery without live DNS timing assumptions.

### Vignette boundary and final qualification (O06)

Add the exact 20 × 20 white-stage case (amount -100, midpoint 65, roundness 0, feather 0) and nearby
positive-feather cases to real shader/readback qualification against the whole-frame reference.
Retain the existing tolerance. A missing adapter is an explicit skip. Hosted Metal readback
shows the hard-edge and near-zero-feather defect below that span, so non-neutral vignettes require a
computed normalized transition span of at least `1e-3` for GPU admission; smaller spans declare the
reference fallback. The frozen reference and output tolerance keep their values. Admission and
reference output are tested without a device, while supported spans retain actual shader/readback
tests. Neutral GPU-shaped drafts return their input unchanged. This conservative admission scope
trades reference-rendering cost at extreme settings for correct edges; it is not a universal GPU
precision or performance claim.
Native M4 and Linux GPU checks, Windows watcher delivery, macOS signing, private corpus and
photo-sized timing remain final qualification outputs, with actual failures/skips retained.

## Integration and acceptance

The root agent owns shared documentation, task status and evidence. Implementers update only their
area's design and list shared-document implications. Builds run serially through `tools/cargo-cached`
on the pinned toolchain. Focused checks accompany each behavior; final formatting, repository
checks, changed-crate Clippy and one quick tier follow finished integration. The standalone ingress
service also runs its own tests and Clippy. Rendered/native gates require their actual environment;
no headless or software-adapter result substitutes for native GPU acceptance.

## Performance review

- Source reads: only known-changed originals receive a streamed verification on the library worker,
  with Locate's single 1 MiB buffer and signature checks. Ordinary presence checks are metadata
  reads; render/export preparation uses the verified-source cache.
- Frames: the work has no production full-frame allocation or rendering operation. The vignette
  regression uses a 20 × 20 synthetic frame and the independent reference. Unsupported near-hard
  vignette settings select the whole-frame reference path and can therefore incur
  its allocation and rendering costs; GPU admission itself is a constant-time metadata check.
- Owner work: indexed durable request lookup and bounded result serialization run inside the
  catalog transactions; permission reconciliation and publication events carry small state. None
  is frame work. Durable results and frozen admissions have an explicit 256 MiB serialized limit,
  separate from the disposable 8 MiB owner cache; an oversized synchronous result rolls back its
  transaction, while an interrupted admitted job cannot restart against new targets.
- Desktop messages: no photo-state/history read, preview request or upload is involved. Unsupported-catalog
  text reads the exported core format constant. Published failures use the event delivery.
- Waiting: resource-lock contention waits on cancellation with a 50 ms acquisition retry only
  while contended. Permission observation exists only while relevant jobs remain. DNS uses four
  lazy process workers, 16 queued jobs and at most 20 retained admissions, with bounded 256-address
  answers and cancellation/deadline wakes. The ingress identifier worker waits for the next stored
  expiry and has no timer when empty.
- Repeated work and caches: a catalog retry reads its durable result before resolving input again.
  Durable answers bypass owner-cache serialization and storage, preserving that cache for the
  session and external-store requests that use it.
  Feed bytes are shared by immutable `Bytes`, one load per target under its own lock, capped at
  4 MiB; active responses may retain an older publication. Concurrent-load tests check identical
  backing-buffer pointers. There is no image cache.
- Measurements: no 24 MP comparison, native GPU or quiet-host timing result is claimed. The required host/corpus work remains in TASK-008. Functional gates test cancellation,
  queue bounds, source preservation and publication/retry behavior; the vignette GPU case requires
  actual shader readback and retains the frozen pointwise tolerance.
