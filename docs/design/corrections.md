# Corrections: Clone, Heal and the repair foundation

Status: **proposal for owner review; planning only**. Clone and Heal are not implemented. The owner accepted the [AI editing](ai-editing.md) scope on 2026-10-05 and decided the repair stage after source development and before colour, deletion of the developer-only `PointReplace` primitive, and the stale-patch rule below. Those decisions are settled; the remaining Clone/Heal contract and numerical choices are this plan's first work. The plan follows the current module, catalog, geometry, stroke and rendering contracts; implementation remains proposed.

The [Corrections task plan](../../tasks/corrections.json) owns offline Clone/Heal, the repair processing primitive, the shared brush interaction and the repair layer's frozen-patch operation. [AI editing](ai-editing.md) owns model qualification, inference, downloads and activation, automatic selection, provider adapters, generation and candidate-review UI. The implemented [module capabilities](module-capabilities.md) already supply settings, resources, jobs and durable artifacts; they are reused, not another delivery slice.

## User result and delivery

The Develop workspace gains a Corrections section with Clone and Heal. Clone copies chosen pixels from another region. Heal borrows detail and adapts it to the destination's tone. Both work offline without accounts, downloads or provider configuration. The person can select a saved operation, change its brush settings or source handle, remove it and change its order. Each change is an ordinary, undoable history entry and has the same semantic API action as the desktop.

Deliver the offline workflow and qualify it independently of frozen patches or AI. Alongside it, extend the same repair layer to accept immutable patches through a bounded host job/result contract, verified with a test producer. AI Remove later uses that foundation; no unavailable mode or provider is drawn as a placeholder. AI's local-first scope, optional remote tier and automatic selection are governed by the AI editing design, not a separate Corrections provider shortlist.

## Editing and module contract

Propose one built-in `luxforge.corrections` module with a single repair effect and an ordered list of operations. Its descriptor declares `single: true`, both source kinds, and `artifacts: true` when frozen patches are added. This plan gives the operation list its own coverage; it does not add mask-bound copies of the repair layer. Each operation has a stable ID, kind, content-space brush references, feather/opacity and a source offset or patch artifact with its coverage and transform. Add, update, delete and reorder are discovered actions. The module owns validation, no-op detection, payloads and compilation; the host owns storage, transactions, history and rendering.

All actions use the current revision envelope and dispatcher deduplication. A module's `ToolModule::label` supplies the history label. Ordinary action retries are durable per asset; `draft.commit` retries follow the owner's current request-table contract and do not outlive the draft's process. No Corrections-specific request log or undo stack is added. Historical preview, undo, redo, restore, named versions and auto-collapsed rows retain the operations and their resources.

The current `ActionDescriptor::preset` flag separates field-patch syntax from preset eligibility. **Proposal to freeze in the contract:** correction-operation actions declare `preset: false`, because their operation IDs, source geometry, strokes and artifacts belong to one photograph. Reuse that gate for preset capture, creation, import and application; add no retouch-preset or Lightroom spot-conversion feature here. Applying an ordinary adjustment preset retains existing repairs and their resource references; upstream changes recompute Clone/Heal and invalidate patches by the same prefix rules as direct edits.

Canvas gestures use the one `draft.*` lifecycle: pointer motion writes no entry; release/Apply commits once; Escape/Cancel discards. A draft conflicts visibly when another client changes its asset; Discard and Reapply use the existing lifecycle. API clients submit complete bounded paths and source coordinates, not pointer events. The first contract task freezes operation identities, action and draft bindings, history labels and the release/Apply rules before implementation.

## Repair placement and image behaviour

The **decided repair stage** is after source development and before colour, in upright content coordinates. Later Basic, colour mixer, Presence and geometry effects apply to repaired and original pixels together. New layers use the registry's stage and order insertion rule; stored layers are never silently rearranged. The developer-only pixel proof and `Processing::PointReplace` are deleted rather than used as the repair primitive. Any unsupported current-shape data is refused explicitly and retained; no migration or compatibility shim is planned.

The current stage vocabulary is `source`, `pixel`, `restoration`, `color`, `spatial`, `geometry`, `finish`. Detail now occupies `restoration`. The owner's repair decision does not specify the relative order of repair and restoration. **Proposal to settle before implementation:** put repair before restoration, so Detail denoises and sharpens repaired and original regions together. Freeze this choice and its consequences for Heal's input and AI-prefix identity in the contract task; do not treat it as an accepted decision.

Clone samples the **prefix before its own operation**, translated by the source-to-target offset, and blends through painted coverage, feather and opacity. Heal uses the same source geometry, adjusts low-frequency tone across the destination boundary and retains sampled detail. A numerical study freezes its solver, convergence bound, colour domain, interpolation and edge rule. Operations cannot sample their own output recursively; overlapping operations see only earlier operations. Brush rasterization, radius, out-of-frame source handling, repeated/short paths and source-handle movement are frozen together, with independent reference fixtures. Clone/Heal recompute from saved geometry and source pixels after upstream changes; they never become stale frozen edits.

The processing primitive declares the destination, every sampled source region, per-patch solve scratch, cancellation checkpoints and admission limits. A source offset can be farther away than a spatial halo, so enlarging the current halo is not a sufficient implementation. Reserve CPU scratch and GPU resources before allocating; refuse over-budget work with a named `resource-limit`, without changing its geometry or quality. The catalog owner and UI thread perform no pixel reads, rasterization, solving or frame work.

## Shared brush and geometry

The delivered host path primitives are already reusable ([one brush system](masking.md#one-brush-system)):

- `ParameterKind::Points`, `path::capture_grid` and `PathCapture` provide bounded capture and deterministic decimation on the stored coordinate grid.
- Consumer-declared `StrokeKind` types share the one content-addressed `StrokeTable`; a stroke is checked as its declared type, and catalog commits write only fresh strokes.
- `StrokeCarrier` declares a consumer's references. `Recipe::stroke_references` currently lists only mask carriers; Corrections must add its repair layer and validate and hydrate those references on every applicable read/write path.
- `DraftTarget` and `declared_target` already derive targets from declared identity parameters. The public `draft.begin` still accepts only `mask` and `component`; `IdentityKind` has no correction-operation kind, and module action declarations still refuse host-only identity parameters. Add the narrow validated operation-identity and draft support needed by this production consumer.

The test-only `path::tests::RepairStroke` proves typed storage reuse; it is not a delivered correction tool. The production desktop brush is still a mask gesture bound to `mask.add-stroke`, and the declared canvas vocabulary is `point-pick`, `sample-apply`, `crop-frame`. Extend the descriptor with the proposed semantic `brush-mask` interaction and generalize the existing capture/overlay plumbing to its declared action and parameters. Corrections declares its own radius, opacity, feather and source payload; it does not adopt the mask brush's flow or colour-limit semantics, or create a second store, capture implementation or draft lifecycle.

Source handles, stroke capture, hit tests and overlays map through the core's current `render.locate`/`render.transform` geometry contract, including nonlinear Lens and Perspective warps as well as crop, straighten, quarter-turn and mirror. Saved geometry stays in content space. Use the shared geometry map and warped-path drawing, with the entry/draft identity that produced the displayed frame; invalid mappings and stale frames have explicit outcomes. Do not assume an affine inverse or duplicate lens/crop mathematics in the desktop.

## Catalog, originals and preparation

The current catalog is format 13, with full immutable recipe snapshots, the shared stroke store and per-entry artifact references. A photograph enters through `pick.develop`, then `source.prepare` and client adoption (`job.adopt`). Tests and tools may use `EditorService::import`, the blocking helper for that same Develop-and-prepare path. No legacy import endpoint, Corrections-owned import pipeline or extra managed copy of the original is added.

The verified source and artifact preparation contract applies to actions, drafts, render, samples, analysis and export. A preparation miss returns the evaluated stack's typed needs through `preparation-required` and the one source job; preparation reads and hashes on a worker. Corrections must also validate and hydrate its typed stroke references through the catalog's existing paths. A missing/corrupt stroke or patch, unavailable module, or unsupported payload fails explicitly, naming the resource and affected operation/layer, while history remains readable.

`source.locate` and folder recovery relink only identical source bytes. A path or volume change with the same fingerprint preserves correction geometry, patch validity and history; the locator is not a rendering-input identity. A missing, offline, replaced or changed original remains a source-availability failure, not permission to render against different bytes or merely mark a patch stale.

Library undo is separate from edit history. Remove/Put back and their undo retain all correction entries, strokes and artifacts; an edited photograph cannot be sent back as an unedited pick. `catalog.empty-removed` is the permission-controlled path that deletes retained edit history and collects only resources no surviving entry names. Its current stroke scan first looks for the serialized `strokes` key, then conservatively finds stored addresses. Corrections must either use that declared carrier shape or extend the scan with its carrier; prove that mask and correction strokes shared by surviving photographs are retained. Keep artifact reachability through the existing `artifact_refs` transaction, collection and live-task protection. Do not create another garbage collector or modify original files.

Select's rendered previews and filmstrip thumbnails must reflect committed corrections, undo and history restoration through the existing entry-keyed preview lane. Reuse its preparation, provider refusal and cancellation contracts, including recovery after Locate. These previews are disposable cache data, not another persisted edit or source.

## Frozen patches and AI boundary

The repair layer's patch operation accepts a validated immutable artifact, coverage, content transform, input-prefix identity and producer provenance. It uses the existing content-addressed `.artifacts` root and host-owned layer artifact list. `CapabilityModule::compile_bound` receives the prepared bytes; rendering never calls the producer, model or remote provider. A patch remains renderable and exportable offline after the model and credentials are removed.

The producer declares dimensions, colour interpretation and mapping. Validate byte/area bounds, alpha and finite values before commit; convert generated pixels to the repair stage's linear representation and composite only inside the saved coverage. Outside-coverage CPU reference pixels are identical to the prefix. GPU results match that reference within the declared output tolerance. Original RAW sensor data and unmodified pixels remain in the continuous pipeline; a generated patch is not recovered sensor data.

The invalidation key must cover the verified source fingerprint and interpretation, source development, content dimensions, upstream layers and masks that affect the input, and **operations before this patch within the same repair layer**, including their stroke/artifact identities. `render::spatial::prefix_hash` supplies layer/mask hashing, but alone omits the source identity and the intra-layer operation prefix. Changes to later operations, downstream colour/geometry, unrelated masks or a same-byte source locator do not stale the patch. The contract task freezes this key and the reported reasons.

A RAW white-balance or earlier-repair change marks the operation **stale** (owner, 2026-10-05). It keeps rendering its frozen patch; its row and the status bar explain why, and `recipe.describe` reports the condition. Extend the shipped `export.plan`/`export.jpeg` flow with stale-operation disclosure and explicit acknowledgement tied to the exported entry and its stale operations. Apply the same rule to `batch.export`: no implicit acknowledgement or silent omission. Freeze the exact request/result shape before code; these extensions do not exist yet. Missing/corrupt bytes still fail explicitly.

Disposable candidates are bounded job results, not durable artifacts or pixel arrays embedded in `job.read` JSON. The current job result carries JSON and published artifact IDs; the foundation task adds bounded host candidate storage and discoverable addressing/read/accept semantics, tested with a producer that needs no model. Use AI editing's accepted starting budgets: at most four candidates of at most 64 MiB each per job and 1 GiB across jobs; account for previews and ownership, report release in `job.read`, and never silently evict a candidate another client is accepting. Only accepted bytes are published through the artifact worker path. Publish on a worker, then recheck the held revision and input prefix at the ordinary atomic recipe commit. A crash or rejected late commit may leave an unreferenced object; it must never leave a partial edit or resurrect an emptied photograph. AI editing owns actual generation, retention policy UI, variations and model/provider failures.

Moving the catalog with its `.artifacts` root preserves accepted patches; copying the database alone reports missing artifacts while retaining history. Settings, secrets and grants remain user-level. The current remote-image grant is still per asset; the owner decided per-provider-profile/data-class consent, implemented with AI editing's remote tier. Clone/Heal and this foundation require no remote consent or local-runtime activation. No old licence gate, two-provider requirement or hosted-first rollout is added here.

## Rendering and responsiveness

[GPU-first rendering](gpu-first.md) is the renderer of record: the GPU draws the picture at rest and in motion, the histogram, samples and export, held to the declared tolerance against the whole-frame CPU reference, and every pixel read goes through the owner's tile service. Corrections' renderer work targets those interfaces and the comparison harness alongside AI editing. Do not build Corrections around CPU proxy settlement, restoration-prefix caches or a point worker, which GPU-first retired; the CPU proxy remains only the drag path of a session without a GPU.

The compiled render boundaries are already centralized in `render/compiled.rs` and the shared pipeline. Extend those seams and the GPU program/plan contracts with bounded region reads and patch solves; do not schedule a new prerequisite refactor of thirty render matches. The whole-frame CPU renderer is the independent reference. Every Clone, Heal and patch primitive has a GPU program qualified for display, histogram, samples and export. A no-GPU fallback names its reason and uses the reference; it never silently omits an operation. Determine any reduced-resolution brush preview behaviour against the frozen numerical contract and label approximation honestly; a proxy must not change saved geometry or stand in for full-resolution acceptance.

Painting draws an immediate vector overlay. Cancel stale drafts/renders, bound points, operation count, coverage, source regions, solve iterations/scratch and GPU texture/buffer residency before integration. Limits live in the shared rendering limits home where applicable; new CPU reference passes use their own `RenderPass` and the shared pool, never RAW's development executor as a render scheduler. The existing 256 MiB spatial scratch target and 2 GiB GPU preview budget are integration constraints, not a promise that a distant Clone read or Heal solve already fits them.

Measure once when the corresponding feature is finished, on 24/60 MP JPEG and qualified RAW on the M4: input-to-overlay, stroke commit, source-handle drag, view/zoom changes, render/sample/export, peak RSS/GPU memory, disk per operation/history and idle CPU. Extend the current mask-only `editor-latency --mode paint` harness for Corrections before claiming it measures this brush. Model load and generation measurements belong to AI editing. Publish misses and measurement scope; headless or VM checks are not native GPU evidence.

## Acceptance and open decisions

Offline acceptance covers independent exact CPU fixtures and GPU reference comparisons; overlap, edges, tiny/large strokes, JPEG and continuous RAW; nonlinear geometry; UI/API parity and conflicts; original hashes; history/versions/reopen; preparation, missing-source recovery, Remove/Put back/Empty Removed; Select rendered previews; and real single/batch JPEG export. The frozen-patch task separately verifies outside-coverage identity, input invalidation, stale export acknowledgement, offline rendering, corrupt/missing artifacts, bounded candidate ownership, cancellation/races, crash recovery and catalog relocation. Model/provider qualification belongs to AI editing and cannot block the offline handoff.

Run only targeted tests while building. Run `quick` once at each finished handoff, `rendered` at UI/image integration, and timing after the corresponding feature work is complete on a quiet host; `full` with the supported RAW manifest precedes a milestone claim. Register the new background-only smoke scenario and its independent checks in the rendered tier; merely running today's scenarios does not prove Corrections. Update the design, module/API documentation, feature status and user guide as behaviour is delivered. A skipped check is not a pass.

Still to freeze: repair versus Detail placement and correction preset eligibility (proposals above), Heal's solver and numerical limits, brush/source-edge behaviour and draft bindings, resource limits, and the candidate/accept and stale-export acknowledgement shapes. The repair stage relative to source/colour, deletion of `PointReplace`, stale patches kept rendering and AI consent policy are already decided.
